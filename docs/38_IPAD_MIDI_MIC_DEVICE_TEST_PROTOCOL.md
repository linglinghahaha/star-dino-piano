# 实体 iPad、MIDI 与钢琴声音测试协议

状态：`protocol_ready / native_runtime_missing / physical_devices_missing / measurements_missing`。

本协议把“iPad 能玩、MIDI 能连、麦克风能听钢琴”拆成可复查测试。它服从 `docs/36_NATIVE_IPAD_AND_APP_STORE_RUNTIME_CONTRACT.md` 的原生行为与 35 项放行门禁，也服从 `docs/09/31-35` 的课程、掌握和输入语义。Web 浏览器或模拟器成功不能替代实体 iPad、真实 MIDI、真实扬声器和原声钢琴证据。

## 一、四种证据等级

| 证据 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 桌面 Web 自动化 | 状态机、触屏模拟、DOM、课程字段和部分输入分流 | iPad 延迟、Core MIDI、AVAudioSession、麦克风准确率 |
| iPad Web/Safari | 触屏布局、Safari 生命周期、Web 离线和扬声器方向性表现 | 原生 Core MIDI 或原生麦克风桥可靠 |
| Xcode 模拟器 | 原生编译、部分布局、数据迁移和权限文案 | 真实触摸、麦克风、MIDI、扬声器、蓝牙、性能 |
| 实体 iPad Release/TestFlight | 指定设备、系统、连接和构建上的真实结果 | 所有 iPad、所有键盘、所有家庭环境或教学效果 |

任何报告必须写清证据等级，不能只写“iPad 测试通过”。

## 二、开始测试前的冻结条件

每次真机测试必须先记录：

- Release/TestFlight build、bundle id、version、build number 和内容 manifest；
- iPad 型号、芯片、容量、iPadOS 版本、方向和可用存储；
- App 首次安装、升级安装或既有安装；
- 输入路线：触屏、USB MIDI、BLE MIDI、内部麦克风或外接麦克风；
- 音频路线：系统扬声器、有线耳机、蓝牙耳机、USB 音频或 HDMI；
- MIDI 设备型号、连接线、转接器、供电、通道和是否使用延音踏板；
- 钢琴类型：数码钢琴、立式钢琴、三角钢琴或其他；
- 房间噪声：安静、普通说话、电视/玩具声、风扇或其他；
- Reduce Motion、对比、减色、声音开关和 App 音量状态；
- 测试档案编号。不得使用真实儿童姓名作为档案名。

若 build、资源 manifest 或课程数据在测试中改变，本轮证据作废并重新开始。

## 三、最低设备矩阵

发布候选至少覆盖：

| 组 | 最低要求 | 目的 |
| --- | --- | --- |
| `D1` | 一台较小或较旧、仍在支持范围的 iPad | 内存、性能、触点和小屏边界 |
| `D2` | 一台主流 10-11 英寸 iPad | 主要目标体验 |
| `D3` | 一台大屏 iPad | 拉伸、留白、琴键宽度和视线跨度 |
| `M1` | 一台实际宣称支持的 USB class-compliant MIDI 键盘 | 主 MIDI 路线 |
| `M2` | 若宣传 BLE MIDI，一台真实 BLE MIDI 键盘 | 配对、延迟、断连和恢复 |
| `A1` | 系统扬声器和一种耳机路线 | 音量、遮盖和路由切换 |
| `P1` | 至少一台真实原声钢琴 | 麦克风音高与噪声验证 |

若最终支持 Lightning iPad 和 USB-C iPad，两种转接路径都必须测试。没有测试过的设备或连接不能写入商店宣传。

## 四、安装、离线和生命周期

按顺序执行并保留结果：

1. 全新安装，无网启动，确认可进入触屏主线；
2. 完成一个短课永久步骤，杀进程重开，确认进度和当前自然停点正确；
3. 设备重启后无网启动，确认资源、设置和故事状态存在；
4. 从旧 TestFlight/build 升级到候选，验证 schema 迁移、重复迁移和失败回滚；
5. 前台等待目标音时切后台，再返回，必须回到 ready/重听，不能把中断前后输入拼成正确答案；
6. 锁屏、解锁、控制中心、通知、电话/FaceTime 类音频中断后恢复；
7. 低内存或系统终止后重开，已完成永久世界状态不能倒退；
8. 家长门执行全部重置，再重启确认孩子进度和本地识别信息按合同删除。

失败时记录精确步骤、前后状态、是否丢失永久进度和是否出现孩子看不懂的技术错误。

## 五、触屏钢琴与真实几何

### 必测行为

- C3-B4 或当前章节要求的键盘完整可见，白键宽度稳定，黑键位于真实 2/3 组边界；
- 旋转、系统栏、分屏状态变化或 Dynamic Type 不改变琴键音高映射；
- 轻点白键中心、靠近白键边缘、靠近黑键底部和两个触点交界，检查误触；
- 连续重复同一键、相邻键交替、快速抬起再按下，不能漏 note-off 或粘键；
- 手指滑过多个键时行为与产品合同一致，不意外产生大量评分输入；
- 多点触控只在 Chapter 5 可选 paired/together 路线使用，核心 relay 始终可单点完成；
- 屏幕琴键的可见标签和 `aria-label` 都只显示字母音名；ARIA 可补充真实键位定位，例如“C，两个黑键左边”，但不得加入 `Do/Re/Mi/Fa/Sol`。按下效果不能改变布局尺寸、遮住字母或把未来答案提前点亮；隐藏听辨不得把某键提前标为当前目标；
- 触摸被系统手势、边缘返回或控制中心抢走时，不得记作错误能力证据。

### 性能

- 触屏到可见键压 p95 目标 `<=50 ms`；
- 触屏到 App 钢琴起音 p95 目标 `<=80 ms`；
- 记录至少 100 次代表性触发，说明测量工具、采样方式、设备和音频路线；
- 这些数字是工程目标，不显示给孩子，也不进入掌握评分。

## 六、Core MIDI 测试

### 连接矩阵

对每条宣称支持的路线执行：

1. App 启动前连接键盘；
2. App 已在前台时连接；
3. 关卡等待输入时断开；
4. 断开后继续触屏完成；
5. 再次连接并继续下一目标；
6. App 在后台时连接/断开，再回前台；
7. 设备休眠、唤醒和重启后重连；
8. 多个 MIDI source 同时存在时选择和去重；
9. 若支持 BLE，测试首次配对、重新配对、距离变差和系统蓝牙关闭。

### 事件合同

- 普通 note-on/note-off；
- velocity-zero note-on 按 note-off 处理；
- 不同 velocity 不改变音高和正确性，只可影响非教学表现且需克制；
- 其它 MIDI channel 不应重复触发或静默漏掉合法输入；
- 延音踏板、调制轮、aftertouch、program change、clock 和 active sensing 不得被当成新琴键答案；
- 连续按住、快速重复、两个相邻音、错误八度和超出课程音域分别处理；
- MIDI echo/loop 不得造成一次按键被评分两次；
- 断连或 stuck note 必须自动清理可见键压和声音状态；
- MIDI pitch 不能写 `actualHand=left/right`。手部证据只来自成人观察或明确的可选手势流程；
- MIDI 不可用时不弹失败页，不丢进度，立即回到触屏。

### 延迟证据

- MIDI 到可见键压 p95 `<=50 ms`；
- MIDI 到 App 钢琴起音 p95 `<=80 ms`；
- USB 与 BLE 分开记录，不用 USB 数字宣传 BLE；
- 记录抖动、最大值和异常次数，而不只报平均值。

## 七、麦克风听钢琴测试

麦克风始终是可选路线。触屏必须完整可玩，麦克风误判不能阻止故事。

### 权限和隐私

1. 只从真实家长门进入说明和系统权限请求；
2. 拒绝后返回触屏，不循环弹权限；
3. 系统设置中后来开启/关闭权限，App 恢复正确；
4. 原始音频不落盘、不上传、不进入日志、诊断或观察附件；
5. 日志只能记录必要的 `confirmed/uncertain/noisy/bleed/octave` 等去身份化状态；
6. 权限文案和 App Store 披露必须与真实网络、文件和 SDK 行为一致。

### 声音情形

对当前课程实际音区逐个测试，不用八度等价冒充准确谱位：

- 单个干净音，弱、中、强三种力度；
- 音头较软和音头较硬；
- 相邻音、错误八度和目标外音；
- 前一个音仍在衰减时弹下一个音；
- 延音踏板造成的泛音与混响；
- 两个音同时响，确认只在产品明确允许的路线解释；
- 普通说话、拍手、电视音乐、玩具声、风扇和房间回声；
- iPad 离钢琴较近、常用距离和较远位置；
- 系统扬声器播放 App 钢琴音时的回授/bleed；
- 内部麦克风与实际支持的外接麦克风分别测试。

### 判定

- `confirmed` 才可作为当前输入；
- `uncertain/noisy/bleed` 不计 wrong，不降低掌握，不触发羞辱反馈；
- 明确听到错误音时可以进入温和比较，但必须保留“系统可能听不准”的成人证据；
- octave 不确定时不得用于需要准确 C3/C4 或谱位的 stable；
- 多次不确定后主动建议触屏/MIDI，但不把孩子赶出故事；
- LP01 仍是固定触屏声音泡泡评分，麦克风不得介入；Chapter 5 simultaneous 证据不得来自单麦克风音高流。

准确率必须按音、音区、力度、距离、钢琴和噪声分别报告。一个安静房间的总体百分比不能代表家庭可靠性。

## 八、AVAudioSession、钢琴音和效果音

- 第一次合法用户动作后音频能启动，不出现永久静音；
- 教学钢琴音前 `540 ms` 保持优先，角色语音、环境声和 SFX 不遮盖音头；
- 正确、错误和完成音效不形成会与当前 Do-Re-Mi 混淆的稳定音高；
- 系统扬声器、耳机、蓝牙、USB 音频切换后音量和路由正确；
- 拔耳机、蓝牙断开、Siri/电话/录屏等中断不会误评分或重复播放目标；
- 声音关闭后仍有清楚但克制的视觉反馈；
- App 音量、系统音量和静音/专注模式行为与产品文案一致；
- 用真实 iPad 扬声器和耳机人工听审舒适度，记录峰值、遮盖、刺耳和疲劳，而不是只看文件 LUFS。

## 九、无障碍和低龄设备检查

- Reduce Motion 后停止持续漂浮、粒子和不必要镜头移动，保留静态因果和真实键压；
- Increase Contrast、Differentiate Without Color 和减色模式下，答案仍能靠名称、黑键组、谱位和动作理解；
- VoiceOver 不提前说出隐藏听音目标；重听控件只描述“重听这个声音”；
- 家长页、权限和设置支持 Dynamic Type，最大支持字号不遮挡按钮或家长门；
- 孩子屏幕触点达到当前发布标准，边缘、最长文字和系统栏无重叠；
- 声音关闭或听力受限辅助可推进故事，但不写 listening stable/retained；
- 视觉辅助不能把自动完成写成读谱掌握。

## 十、长时间和恢复压力测试

在最旧支持设备上至少执行：

- 连续 30 分钟循环短课、地图、家长页和设置；
- 多次进入/退出 MIDI 和麦克风路线；
- 20 次前后台、10 次音频路由变化、10 次 MIDI 热插拔；
- 多次完成、重玩、自然休息和档案重置；
- 观察内存、温度、帧率、音频失效、重复事件、粘键和永久状态倒退。

主游戏稳定帧率最低 30fps，常规目标 60fps。若热降频造成输入错位、音频爆裂或动画与评分不同步，发布门禁失败。

## 十一、证据表

每个失败或通过记录至少包含：

| 字段 | 内容 |
| --- | --- |
| Test ID | 例如 `D2-M1-MIDI-HOTPLUG-03` |
| Build | version/build/content manifest |
| Device | iPad 型号、iPadOS、方向、可用空间 |
| Hardware | 键盘/钢琴/耳机/转接器/供电 |
| Route | touch、USB MIDI、BLE MIDI、internal mic、external mic |
| Preconditions | 权限、网络、设置、档案状态 |
| Steps | 可重复的编号步骤 |
| Expected | 课程与平台合同规定的结果 |
| Actual | 实际结果，不写模糊“正常” |
| Timing | p50/p95/max、样本数和测量方法，若适用 |
| Evidence | 截图、录屏、Xcode Instruments、日志或人工听审编号 |
| Privacy | 是否包含原始音频或个人信息；正常应为否 |
| Status | `passed/partial/missing/contradicted` |
| Severity | `P0/P1/P2/P3` 与受影响关卡 |

孩子或家庭的可识别信息、原始麦克风录音和账户信息不得进入普通证据目录。设备序列号也不需要记录。

## 十二、放行与宣传边界

- 触屏核心路线只有在全部支持设备上通过，才能称“无需 MIDI 也能完整玩”；
- USB MIDI 只有测试过的实际路径通过，才能宣传可靠支持；
- BLE MIDI 未完成设备矩阵时不得写“支持蓝牙钢琴”；
- 麦克风只有在真实钢琴、音区、力度、距离和家庭噪声矩阵达到批准标准后，才能作为实验或正式功能描述；
- 麦克风仍不得成为硬门槛，也不得宣传成专业调音器或精确演奏评测；
- 浏览器 Web MIDI、模拟 MIDI 或一台桌面键盘不能支持 iPad 原生 MIDI 宣传；
- 所有营销文案、Review Notes 和 App Store 截图只展示最终 Release 已验证行为。

## 十三、当前结论

- `passed`：设备、触屏、MIDI、麦克风、音频会话、生命周期、性能、无障碍和证据记录协议已锁定。
- `missing`：没有原生工程、实体 iPad、USB/BLE MIDI、原声钢琴、真机时延、准确率、混音或长时间压力测试结果。
- `locked_by_native_environment`：Web M08/Chapter 1-2 已在 `overhaul-338a` 形成独立通过的浏览器基线；当前仍缺 macOS/Xcode、实体 iPad 和原生 N0 工程，因此不得创建伪造的 Core MIDI、麦克风、AVAudioSession、真机时延或 TestFlight 通过记录。
- `release blocked`：本协议中与实际产品宣传相关的设备路线未形成 authoritative evidence 时，项目不能称为成熟 iPad App。
