## Accepted Workshop Teaching And Review Direction

The proposed workshop loop is useful, but it must be implemented as fading scaffolding rather than a permanent color-matching game.

Accepted for implementation:

- guided parts use a large child-facing solfege mark plus a smaller letter badge such as `Do` + `C`;
- the approved note palette may appear as a thin edge, small energy seam, or badge accent; whole-object recoloring is optional and must not be the only differentiator;
- after no input, Xingya gives staged help: a non-answer gesture, then the allowed note-name clue, then a black-key locator and/or target-sound replay;
- parent/teacher records add first-input and correct-response timing, accuracy, first-try accuracy, hint level, input route, and common wrong-note pair;
- missed items return later inside a dedicated review/check segment, with spacing and a retry cap;
- child rewards are cumulative story stars for completion, recovery, and reduced-cue independence.

Modified from the original proposal:

- timing is observation data only. There is no child countdown, speed bonus, speed penalty, or speed-based mastery claim;
- do not use a competitive rank ladder for ages 4-6. Numeric performance details stay parent-facing, while the child earns named story stars without losing previously earned stars;
- do not move a missed construction step to the end if that would break story causality. Repair the current build action immediately, then revisit the note later as a separate review object;
- do not keep `Do/C`, the strong note color, locator, and glowing target key all visible in reduced-cue checks. At least the answer color/glow must be delayed until a wrong input or an explicit help stage;
- an answer-revealing inactivity hint changes the run's cue evidence and therefore cannot silently count as an unassisted `stable` result.

Implementation boundary:

- the prototype task may implement the visual badge system, timer instrumentation, local telemetry fields, hint-state UI, and parent presentation;
- exact idle delays, review spacing, retry caps, and any parent-only composite score require curriculum-side confirmation or an explicit authoritative rule before they become mastery semantics;
- all child data remains local for the prototype. Do not add analytics, cloud sync, or export without updating the child-data and parent-gate contracts.
