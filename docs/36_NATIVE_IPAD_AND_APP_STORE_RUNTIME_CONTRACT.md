# 原生 iPad、Core MIDI 与 App Store 运行合同

状态：`specification_passed / web_reference_ready_at_338a / architecture_choice_open / native_runtime_missing / mac_xcode_account_device_store_evidence_missing`

负责人：课程故事、整体调度与独立审查任务锁定行为、教学、隐私和放行证据；未来原生 iPad 任务拥有 Xcode 工程和原生桥接写入权；Web 原型任务只提供已通过的行为参考；媒体任务只交付经批准的运行格式与来源台账。

本文件规定“Web 原型怎样变成成熟 iPad App”，不预先强制 SwiftUI、SpriteKit、WKWebView 或 Capacitor 中的某一种架构。任何实现都必须证明相同行为、离线、音频、MIDI、隐私、家长门、无障碍和 App Store 结果，不能用“已经打包成 IPA”代替产品通过。

`38_IPAD_MIDI_MIC_DEVICE_TEST_PROTOCOL.md` 是本合同的实体设备执行方法；它不能改变本文件的门禁，只负责证明指定 build、设备、MIDI、麦克风和音频路线是否真实达到门槛。

## 给家长看的简短说明

孩子不用 MIDI 键盘也能完整玩，触屏始终是主路线。连接 MIDI 后，App 可以在家长设置完成后接收真实琴键；打开麦克风后，也只能在本机临时听钢琴音，不保存或上传家庭声音。

制作和提交原生 iPad App 需要能够使用 macOS、Xcode、实体 iPad 和 Apple Developer 账号，但不等于必须立刻购买一台自己的 Mac。可使用自有、借用、单位或合规云端 Mac；最终签名、真机、TestFlight 和提交证据仍必须真实完成。

## 一、不可改变的产品边界

- 五章课程、level/bundle id、音高/音区/谱位、短课边界、提示递减、故事结果和 `played/stable/retained` 语义继续以 `docs/03/09/14/17/24/31-35` 为准。
- 原生实现不能为了迁移方便删掉触屏路线、自然停点、错误修复、同等奖励或家长证据，也不能把章节重新做成连续闯关。
- 触屏必须完成全部核心故事。Core MIDI 和麦克风始终是可选输入，权限拒绝、设备断开或识别不确定不能卡住孩子。
- 第一、二章完整气密服、第三章首次空气检测开盔、咚咚三角/四足低姿和第五章安全控制区合同保持不变。
- 教学钢琴音优先；角色语音、Foley、环境和奖励动机不能遮盖目标音。
- App 默认无账号、无广告、无社交分享、无儿童自由文本、无第三方行为分析、无云同步和无运行时下载课程。
- A-G 英文单词模式继续停在主课程和原生核心放行之后。

## 二、进入原生工作的阶段

### N0 环境与可行性探针

当有 macOS/Xcode 和实体 iPad 可用，且 Web 至少已有一个稳定教学纵切时，可以做不改课程的技术探针：

- Release 配置能安装到真机；
- 一个真实几何触屏琴键能即时发声；
- Core MIDI 能发现、连接、断开并接收精确 note-on/off；
- 麦克风权限和本地音高状态机可以由家长门进入；
- 本地进度能在杀进程、重启和版本迁移后恢复；
- 无网冷启动可进入可玩触屏页面。

N0 只证明平台可行性，不建立 App Store 或课程完成声明。没有 Mac 时继续 Web 课程和素材工作，不伪造 Xcode/TestFlight 证据。

2026-07-12 状态：`overhaul-338a` 已满足“至少一个独立通过的 Web 教学参考”前置条件。N0 仍不能开始，因为当前没有可核验的 macOS/Xcode、实体 iPad、签名账号和原生工程环境；等待这些条件不妨碍继续完成 Web 课程、素材和审查。

### N1 原生纵切

选择一个已通过 Web 独立审查的短教学链迁移，至少覆盖：地图进入、触屏、正确、错误、帮助、自然休息、家长证据、离线恢复、声音关闭和减少动态。Core MIDI/麦克风仍可缺席，但触屏必须完整。

### N2 全课程迁移

只迁移已冻结的五章合同。每章分批通过行为对照，不在原生重写时顺便改音序、阈值、故事或奖励。

### N3 TestFlight 与商店

行为、设备、隐私、素材和外部观察通过后，才冻结 TestFlight 候选、App Store 元数据和提交答案。

## 三、实现架构和离线边界

允许：

- 全原生 SwiftUI/SpriteKit/AVFoundation/Core MIDI；
- 打包本地 Web 内容的 WKWebView/Capacitor 壳层，加原生音频/MIDI/权限桥；
- 经技术探针证明更合适的混合方案。

无论选哪种方案，都必须满足：

- 课程、图片、音频、字体和运行代码随 App 包或受审的本地资源一起交付；核心孩子流程不依赖远程网页、CDN、登录或服务端配置。
- 若使用 WebView，不能从公开 URL 加载主游戏；原生桥必须有版本、事件 schema、超时、错误和取消合同。
- 原生媒体回调不能直接写 mastery、完成或下一关，只能报告媒体状态；学习状态仍由课程状态机决定。
- Web Service Worker 通过不能冒充原生离线通过；IPA 内资源、首次安装、升级和无网冷启动需单独验证。
- Web `localStorage` 不自动等于原生迁移。默认原生从新档案开始；任何 Web 进度导入都必须以后单列家长门、数据格式和隐私审查，不能静默读取浏览器数据。

## 四、触屏与真实琴键几何

- Chapter 1-3 保持真实中音键盘；Chapter 4-5 保持连续 `C3-B4` 两八度，不拆行、不分页、不在作答中滚动。
- 白键等宽，黑键只位于真实边界；B-C、E-F 无黑键。布局、标签、按下状态和触点不能改变几何。
- 视觉按下和钢琴起音必须立即响应，不等待故事动画或网络。
- 多点只用于可选 paired/together；核心路线不依赖多点。
- Apple Pencil、手掌、滑动、长按、系统手势和边缘误触不能伪造多个音或第二个配对音。
- safe area、Home indicator 和系统悬浮控件不能遮挡当前键、谱位或家长门出口。

## 五、Core MIDI 合同

- 使用 Apple 原生 Core MIDI 路径；Web MIDI 代码不是原生可靠性证据。
- 支持的连接类型必须按实际测试声明。若宣传 USB、蓝牙 MIDI 或特定转接器，就分别提供真机证据；未测类型不写入营销。
- 正确处理 note-on、note-off、velocity-zero、running status、时间戳、重复抖动、通道、设备热插拔和前后台恢复。
- 只接受精确目标 MIDI 和音区；八度等价音不能写 staff/register stable。
- 外接琴自身发声和 App 确认音并存时，必须人工听审双响、延迟和梳状感；设置可只保留视觉确认或降低 App 回声。
- MIDI 断开后立即回到可用触屏，不弹失败页，不清空当前永久故事状态。
- MIDI 音高不能推断实际左右手、指法、姿势或技术；成人确认字段继续独立。

## 六、麦克风与家庭声音

- 麦克风入口位于真实家长门后；孩子首次进入关卡不直接看到系统权限框。
- 权限说明必须写明“听钢琴单音、可不用、只在本机处理、原始音频不保存不上传”。
- 只在目标回放结束后打开识别窗，区分 confirmed、uncertain、noisy、speaker-bleed、octave-ambiguous 和 permission-denied。
- uncertain/noisy 不算孩子错误，触屏始终能接管。
- 麦克风只推动合同允许的 sequential played；在完成真机校准前不单独授予 stable/retained，也不提供 paired/together 证据。
- App 不录制、不缓存、不导出家庭麦克风流。崩溃日志、诊断包和系统分享也不得包含原始音频。
- 用户与孩子预录的角色台词是制作资产，不是运行时收集。原 WAV、授权和处理链遵守 `docs/28_*` 的私密门禁；App 只打包获批衍生文件。

## 七、原生音频会话

- 教学钢琴音、角色语音、SFX、环境和奖励使用分离总线；`noteBus` 不被 duck。
- 目标音起音后的前 540ms 延续现有遮盖合同；角色语音尽量在目标音前结束。
- 分别验证扬声器、耳机、USB 音频、蓝牙输出和外接 MIDI 琴自身发声；未支持路线不宣传。
- 来电/闹钟/Siri/控制中心/耳机拔出/蓝牙切换/前后台等中断后，App 暂停评分，恢复时回到明确 ready 状态，不把系统噪声或恢复音算输入。
- 静音、系统音量、App 内钢琴/效果音设置和减少动态状态在重启后保持；孩子端不能误触进入危险响度。
- 不使用自动播放解决 iOS 音频策略；正式 session 由孩子/家长可理解的手势进入。

## 八、本地数据、迁移与删除

原生数据至少分开：

```text
contentVersion
schemaVersion
formalSessions
storyProgress
playedEvents
stableEvents
retainedEvents
todayNeedsPractice
inputCapability
parentSettings
accessibilitySettings
```

- debug/direct 记录与正式学习证据分离；媒体、程序输入和 modeled success 不能污染 child correct/inputRoutes。
- stable/retained 历史不因后来困难被删除；当天支架单独记录。
- 数据迁移逐版本、可重复、失败可回滚；升级不能把 played 变 stable、把同日记录变 retained 或重置永久故事物件。
- 家长设置提供“重置今天提示”“重置全部本地进度”和清晰二次确认；孩子端不能误触删除。
- 卸载、系统备份、设备迁移和本地重置的实际行为写入隐私说明。默认不启用 iCloud/账号同步。
- 发布归档保存 schema、迁移夹具、重置测试和回滚说明，不只保存最新数据库样本。

## 九、家长门与受限表面

真实家长门至少保护：

- 麦克风权限说明与系统权限触发；
- MIDI/音频高级设置；
- 外部支持、隐私和法律链接；
- 购买、订阅、恢复购买；
- 数据导出、导入、重置和诊断分享；
- 任何账号、云同步或教师功能（若以后增加）。

要求：

- 不能只是“家长请点这里”或孩子容易反复试出的单按钮。
- 挑战对成人可理解、对低幼有实际阻力，失败不暴露答案；无障碍成人仍能完成。
- 权限拒绝后不循环弹系统框；孩子触屏路线继续。
- 家长页支持 Dynamic Type、VoiceOver、明确返回孩子流程，并且不会把调试统计暴露成孩子分数。

## 十、儿童数据与 App Store 隐私

- 每个本地字段、权限、日志、SDK、网络请求和处理目的进入发布 child-data map。
- 提交前完成 App Privacy 问卷、隐私政策、`PrivacyInfo.xcprivacy`/所需原因 API 清单、麦克风用途字符串和第三方 SDK 隐私清单；内容必须与 Release 包实际行为一致。
- 默认没有第三方分析、广告、归因、社交、崩溃上传或远程配置 SDK。若未来增加，必须先重新打开地区儿童隐私、家长同意、数据保留和删除审查。
- 网络关闭时核心孩子流程完整；任何支持/隐私链接只在家长门后打开系统浏览器。
- 日志不得包含儿童姓名、自由文本、原始音频、完整 MIDI 流或可识别家庭信息。
- App Store Kids 年龄段在元数据冻结前明确选择。当前 UI 先按“5 岁及以下”的不依赖阅读标准设计，同时让 6 岁儿童可用；最终声明仍需对照当时 Apple 规则和真实观察。

## 十一、生命周期、离线和恢复

- 首次安装、无网冷启动、升级后首次启动、杀进程重开、设备重启均进入可恢复页面。
- Child task 以 iPad 横屏为主。若只支持横屏，在工程和商店元数据中一致声明；若允许旋转，旋转时暂停评分并恢复同一目标，不能重排琴键造成误按。
- 前后台、低内存、音频路由变化、MIDI 断开、麦克风中断和系统权限变化都不清空已完成的永久步骤。
- session 正在目标音播放或等待输入时被中断，恢复后重置到 ready/重听，不把中断前后的输入拼成正确答案。
- 所有核心资源在飞行模式可用；网络失败不显示技术错误给孩子。

## 十二、无障碍与低龄公平

- 支持 Reduce Motion、Increase Contrast、Differentiate Without Color 和声音关闭；设置来源和 App 内设置有明确优先级。
- 色彩永远是次级线索；减色后字母、黑键组、谱位、角色动作和世界因果仍可理解。
- VoiceOver/无障碍树不得提前泄露隐藏听音目标；重听只叫“重听这个声音”。正常琴键可说自身名字，但不能标“当前正确答案”。
- 家长页和权限页完整支持 VoiceOver/Dynamic Type；孩子主游戏至少有稳定焦点顺序、可识别控件和不挡琴键的辅助标签。
- 听力受限或不愿使用声音的孩子可用可见模型/共同完成推进故事，但不能因此写 listening stable/retained；家长端如实显示所用支架。
- 视觉受限会影响五线谱目标，不能用自动完成伪称读谱掌握；需要以后与无障碍顾问决定适当替代体验和声明。
- 触点、文本、长单词、状态图标和系统字体在支持设备上无重叠、截断或小于可靠触摸尺寸。

## 十三、设备与性能证据

所有设备矩阵、时延、麦克风条件、生命周期和压力证据按 `docs/38` 记录；“能连上一次”或模拟器截图不构成通过。

TestFlight 前冻结：最低 iPadOS、支持方向、目标 iPad 尺寸、芯片/内存下限和支持的 MIDI/音频连接。

最低设备矩阵至少覆盖：

- 一台较小/较旧的受支持 iPad；
- 一台主流 10-11 英寸 iPad；
- 一台大屏 iPad；
- 系统扬声器和耳机；
- 至少一条实际宣称的 USB MIDI 路线；
- 若宣传蓝牙 MIDI，再加一台 BLE MIDI 设备；
- 至少一台原声钢琴和一种普通家庭噪声环境。

目标性能门槛需由真机工具记录：

- 触屏/MIDI 到可见键压 p95 不高于 50ms；
- 触屏/MIDI 到 App 钢琴起音 p95 不高于 80ms；
- 主游戏稳定帧率不低于 30fps，常规目标 60fps，无持续掉帧或热降频导致的输入错位；
- 无网冷启动在支持设备上可接受，发布前记录真实时间而不是只写目标；
- 内存告警、前后台和长时间短课循环无崩溃、音频失效或状态重复。

这些是工程验收目标，不是商店营销数字；若教师/儿童测试证明还需更严格，应收紧。

## 十四、App Store 与 TestFlight 证据

- Release 构建、签名、bundle id、版本、build、内容版本、资源 manifest 和截图证据必须指向同一候选。
- TestFlight 内部测试先过安装、升级、权限、离线、输入、恢复和崩溃；外部儿童测试只使用隐私/授权已经准备好的候选。
- App 图标、预览视频、截图和描述全部来自实际最终行为，不展示未实现 MIDI、麦克风、角色动作或章节。
- Review Notes 清楚说明：触屏可完整玩、麦克风可选且本地不存储、MIDI 需要实际设备、家长门位置和 Kids 内容路径。
- 所有图片、动画、角色语音、SFX、钢琴音源、字体、旋律和商店媒体有来源、授权、处理记录和最终哈希。
- 商店提交前重新核对当时 Apple Review Guidelines、Kids Category、隐私问卷和所需原因 API；旧文档日期不能替代提交时事实。
- 年龄段、定价、一次性购买/订阅/免费策略和地区范围在 metadata freeze 前明确；未决定项阻止提交但不阻止课程原型。

## 十五、必须自动或可重复验证的门禁

1. Release 配置可归档、安装并启动，版本/内容版本/manifest 一致。
2. 核心游戏资源随 App 本地交付；无网冷启动可进入触屏流程。
3. 五章正式 id、音序、音区、谱位、bundle 和 mastery 规则与 Web 冻结合同一致。
4. 触屏能完成全部核心路线，权限拒绝和无 MIDI 不阻塞。
5. 中音和 C3-B4 两八度键盘几何、黑键边界和触点在设备矩阵正确。
6. safe area、横屏、旋转/方向声明和系统栏不遮挡教学区。
7. 正确、错误、repair、modeled、rest 和刷新恢复不污染证据。
8. debug/direct 不创建正式 completion/stable/retained。
9. schema 迁移、重复迁移、失败回滚、全部重置和永久故事恢复通过。
10. Core MIDI note-on/off、velocity-zero、抖动、错误八度、热插拔和前后台通过。
11. MIDI 断开立即回到触屏，当前永久进度不丢失。
12. MIDI pitch 不写 actual hand；paired/together 证据遵守 Chapter 5 合同。
13. 麦克风权限只从家长门触发，拒绝后不循环请求。
14. 麦克风 confirmed/uncertain/noisy/bleed/octave 状态分开，uncertain 不算 wrong。
15. 原始麦克风音频不落盘、不上传、不进入日志或诊断。
16. 音频中断、耳机/蓝牙/USB 路由变化和恢复不会误评分或静音失效。
17. 教学音前 540ms 优先、效果音上限、声音关闭和角色语音时序通过。
18. App 重启后音量、声音、减少动态、对比和家长设置保持。
19. hidden listening 目标不出现在可见层、VoiceOver、日志或原生桥消息的孩子可见字段。
20. Reduce Motion、对比、减色、声音关闭和 Dynamic Type 无布局重叠。
21. 听力辅助/共同完成可继续故事但不授予 listening stable/retained。
