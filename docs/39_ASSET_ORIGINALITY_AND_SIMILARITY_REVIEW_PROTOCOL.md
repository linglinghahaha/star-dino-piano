# 素材原创性、版权来源与外部相似性复核协议

状态：`protocol_ready / internal_review_partial / external_professional_review_missing / release_clearance_missing`。

本文件不是法律意见，也不能保证不存在第三方权利。它规定项目怎样保存来源、拒绝高风险素材、进行独立相似性复核，并在 App Store 发布前把角色、场景、界面、音乐、声音、字体和宣传素材收敛成可审计的原创包。

## 一、为什么“没有直接复制”仍不够

风险不只来自复制文件，还可能来自：

- 让生成模型模仿某个商业角色、动画、玩具或在世艺术家风格；
- 虽然重新绘制，但轮廓、配色、胸前装置、头盔、招牌动作和故事定位组合过于接近；
- 把竞品截图的界面结构、文案、角色站位和奖励方式整体搬过来；
- 使用熟悉旋律的改音、改节奏或短片段；
- 从影视、游戏、短视频或素材包截取音效；
- 购买或生成素材后没有保存许可、服务条款、提示词和最终哈希；
- 用“AI 生成”误认为自动拥有清晰版权或不会撞形。

Codex、生成模型和普通内部审图只能做风险筛查，不能代替发布地区的专业法律意见。

## 二、每个正式素材的来源包

`docs/16_ASSET_MANIFEST.md` 是运行台账。每个 release asset 还必须能追到以下来源包：

| 字段 | 必须记录 |
| --- | --- |
| Asset ID | 稳定唯一编号，不只靠文件名 |
| Final path | Release 实际引用路径 |
| Type/use | 角色、动作、背景、道具、UI、字体、音乐、SFX、语音或商店媒体 |
| Creator/tool | 人类作者、内部代码、模型/服务名称和版本 |
| Generation date | 生成或制作日期 |
| Prompt/brief | 完整制作要求及禁止模仿边界；敏感密钥不得进入记录 |
| References | 所有输入参考及其权利状态；没有参考也明确写无 |
| Source files | 可编辑源稿、原始录音或生成原件的位置 |
| Edits | 裁切、重绘、合成、变调、降噪等人工处理 |
| License/terms | 购买凭证、许可文本、生成服务当时适用条款或原创声明 |
| Final hash | Release 文件 SHA-256 |
| Runtime proof | 实际页面/触发点和 build id |
| Similarity review | 内部和外部审查日期、审查者、结论、比较范围 |
| Status | `source_concept / provisional / approved / rejected / retired` |

只有最终文件有哈希、但没有来源和参考记录，不算 release-ready。只有源稿存在、但运行引用的是另一份未记录文件，也不通过。

## 三、绝对禁止的输入和制作方式

- 不使用奥特曼或其他商业英雄、动画、电影、游戏、玩具角色的名称、图片、剪影或服装作为生成参考；
- 不写“做成某品牌、某工作室、某在世艺术家、某具体作品的风格”；
- 不上传竞品完整截图让模型复刻界面，只能提取抽象问题，例如“信息太多、主任务不清”；
- 不描摹商业角色的头型、眼睛、胸前装置、变身器、武器、必杀姿势或标志性光线；
- 不从受保护音乐、视频或游戏中采样旋律、伴奏、角色叫声、UI 音或环境声；
- 不使用来源不明的“免费素材”、搜索结果图片或社交媒体文件；
- 不接受模型在画面中生成的品牌、文字、标志、水印或疑似签名；
- 不把被拒绝的 concept、技术预演或 Grok/Gemini 能力探测复制到 runtime 改名冒充批准素材。

## 四、角色原创性锁定

### 星芽

正式版本必须共同保持：

- 原创星芽龙身份，三颗头芽、圆润幼龙脸、尾巴比例和星星背包；
- 外勤状态为完整气密服、透明头盔、手套、靴子、生命维持背包和尾套；
- 不出现胸灯、变身器、计时器、武器、披风、战斗装甲分片或英雄光线姿势；
- 头盔是探索装备，不成为永久头部或掩盖三颗头芽；
- 花园模式与气密服模式必须明显是同一个角色。

### 咚咚

正式版本必须共同保持：

- 低姿四足幼年三角龙；
- 一根鼻角和两根眉角，颈盾圆润，不增加额外角状尖刺；
- 低音、地基、地下生态站是故事职责，不使用战斗冲撞或怪兽化形象；
- 与星芽在比例、线条、材质和表情语言上属于同一原创世界。

角色动作表逐张检查头芽/角数、脸型、尾巴、装备、手脚数量、背包和颜色。模型生成的一张定稿不能证明其它动作自动一致。

## 五、视觉相似性审查维度

每个主要角色、App 图标、首页地图和商店首图至少按以下维度比较：

1. 整体剪影和身体比例；
2. 头部、眼睛、嘴、角/头芽和耳朵结构；
3. 服装、头盔、背包、胸前装置和道具；
4. 主色组合、色块位置和高识别装饰；
5. 招牌动作、表情和镜头构图；
6. 名称、口号、角色关系和故事设定；
7. App 图标轮廓和缩小后的第一识别信号；
8. UI 信息架构、按钮布局、奖励图标和关卡地图；
9. 生成提示词是否主动指向具体 IP；
10. 普通家长第一眼是否会说“这就是某某角色/某某 App”。

通用题材如恐龙、星球、钢琴、五线谱、头盔和起重机可以使用，但多个高识别元素与同一商业作品集中重合时必须重做。

### 内部退回规则

- 提示词、参考图或源文件直接包含受保护角色：`P0 / rejected`；
- 与同一知名角色在剪影、面部、服装装置或招牌动作中出现两个以上高识别组合重合：`P1 / redesign`；
- 只有通用题材或单一普通颜色相似，没有整体来源联系：记录为低风险，不因“都是恐龙/太空”自动拒绝；
- 无法解释来源或模型输出含品牌/水印：保持 `provisional` 或拒绝，不能进入发布包。

阈值是内部风险控制，不是法律测试。外部专业审查可以要求更严格。

## 六、生成图像和视频审核

每批生成素材必须保留：

- 生成模型、版本、日期、完整 prompt 和输入参考；
- 原始输出与最终裁切/透明化/压缩文件；
- 接触表和逐项人工检查；
- 角色数量、头芽/角/肢体/尾套、透明边界、烘焙文字、品牌和异常结构；
- 视频首帧、中间帧、尾帧、分辨率、帧率、时长、音轨和透明/背景事实；
- `runtimeApproval=false` 的候选不能由文件移动或 CSS 引用自动变成批准。

生成模型自称“原创、无版权风险、适合儿童”不能作为证据。必须由项目外的成人审查输出本身。

## 七、界面和竞品参考边界

- 可以研究竞品解决什么问题、用户为什么迷失、哪些流程有效；
- 不复制竞品屏幕、角色、插图、文案、关卡名称、动画、图标集合或整体版式；
- 熟悉的系统图标使用平台或已许可图标库，不从截图抠图；
- 真钢琴黑键几何、五线谱位置和通用按钮符号是功能事实，应准确实现；
- 本项目的差异化结构是“音乐输入直接改变原创故事世界、提示递减、故事通过与掌握分离”，不能靠换皮复刻竞品；
- 用户提供的截图只作为问题/审美参考时，记录“抽象采用了什么、没有复制什么”。

## 八、音乐、旋律和钢琴音

每首运行旋律保存：

- 作曲者/生成方法和日期；
- 音高、音区、节奏、拍号、速度范围和可读谱面/MIDI；
- 是否使用任何参考曲、采样或模型服务；
- 原始工程、导出文件和 SHA-256；
- 教师准确性审查和外部相似性复核。

不得使用奥特曼、动画、电影、游戏、儿歌录音或其它熟悉商业旋律。简单音阶和基础音型可能属于通用材料，但若节奏、音程、配器和乐句组合让普通听者明显联想到同一首受保护作品，应重写。

第五章固定两小节原曲只能使用 `docs/03/24/35` 的 canonical 版本。任何媒体任务不能为了“更好听”临时替换旋律。

钢琴采样若以后替换 WebAudio 合成，必须保存音源许可、录音者授权、采样范围、处理和发行权。A4=440 或标准音高本身不是版权许可。

## 九、音效、语音和录音

- 优先使用项目原创 DSP、Foley 或明确许可的生成/录制素材；
- 不从影视、游戏、短视频或素材演示音频中截取；
- 每个 SFX 保存来源、配方/原录音、许可、处理、响度、峰值、触发点和哈希；
- 角色固定台词必须有表演者授权和用途范围；
- 儿童声音默认采用固定台词录制与轻度处理，不训练可复用克隆模型；
- 未经新的明确授权，不上传、训练、共享 voice id 或公开真实儿童原声；
- 被处理后的声音仍不能模仿已知商业角色的声线、口头禅或叫声。

## 十、字体、图标和第三方代码素材

- 系统字体、开源字体、图标库和第三方 UI 组件分别保存许可和版本；
- 字体文件是否允许 App 内嵌、商用、子集化和修改必须明确；
- 不从商业 App 截取图标；
- 手工 SVG、CSS 图形和代码生成谱表记录作者与来源；
- App Store 包中的第三方 SDK、字体和媒体与隐私/许可清单一致。

## 十一、外部独立复核

内部筛查完成后，发布前至少安排：

1. 一名没有参与素材制作的人做视觉/听觉盲审；
2. 针对主要角色、图标、首页和关键商店图进行外部相似性搜索和比较记录；
3. 一名音乐教师或音乐专业人员复核主要旋律与钢琴音准确性；
4. 对目标发布地区进行版权、商标、儿童声音授权和隐私专业复核；
5. 对最终 Release 包重新扫描，确认实际引用文件与审查包哈希相同。

外部审查报告至少写明审查范围、比较方法、发现、无法判断项、要求重做项和最终文件哈希。只说“看起来没问题”不能作为发布证据。

## 十二、App Store 和市场材料

- App 名称、图标、角色名、宣传语和截图不得暗示与任何商业 IP、影视公司或玩具品牌有关；
- 不在关键词、描述或广告中借用受保护品牌名称引流；
- 截图、预览视频和文案只展示最终实现，不展示被拒绝概念或未完成硬件功能；
- “原创”“儿童安全”“支持 MIDI/麦克风”等声明分别由本协议、隐私审查和 `docs/38` 真机证据支持；
- 发布后若收到权利投诉，冻结相关素材、保存版本和来源记录，由专业人员处理，不自行删除证据或继续分发。

## 十三、放行表

每个主要素材包最终必须回答：

| 问题 | 状态 |
| --- | --- |
| 来源、prompt/brief、参考和许可是否完整 | `passed/partial/missing/contradicted` |
| 原始、编辑和最终文件能否追溯 | `passed/partial/missing/contradicted` |
| 最终运行引用与审查哈希是否一致 | `passed/partial/missing/contradicted` |
| 是否含品牌、文字、水印或异常结构 | `passed/rejected` |
| 角色/场景/动作是否符合项目圣经 | `passed/partial/rejected` |
| 内部相似性审查是否通过 | `passed/partial/rejected` |
| 外部独立相似性审查是否通过 | `passed/partial/missing/rejected` |
| 音乐/声音/字体权利是否完整 | `passed/partial/missing/rejected` |
| App Store 实际包是否只引用 approved 素材 | `passed/partial/missing/contradicted` |

任一运行素材为 `missing`、`contradicted` 或 `rejected`，成熟 App 发布门禁失败。

## 十四、当前结论

- `passed`：来源包、角色锁定、相似性维度、生成素材、UI、音乐、声音、字体和外部复核协议已经明确。
- `partial`：当前项目已有原创世界、资产台账、生成 prompt/候选隔离、若干哈希和内部版权边界。
- `missing`：所有最终素材的统一来源包、最终哈希、独立盲审、外部相似性搜索、音乐专业复核和发布地区法律审查。
- `release blocked`：外部专业复核和最终 Release 引用扫描完成前，不能声称素材已经获得完整版权清关，也不能称成熟 App 可发布。
